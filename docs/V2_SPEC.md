# V2：探索性历史比较 / 分期验证

本文件包含第一阶段比较、第二阶段多窗口及第8节独立数据准备/离线浏览扩展。V1_SPEC.md 的策略、成交、账户、指标与已验收 Funding 修复契约继续有效；不放松验证、不增加搜索、优化、组合、显著性筛选、模拟盘或实盘。单体 Python 离线 CLI，复用 V1 账户和报告，不引入新运行依赖。

## 1. 比较输入与成员

命令：`qfs compare --config <JSON>`。配置为 V1 公共配置去掉 `strategy`：symbol、start/end、data 四路径、initial_equity、position_fraction、maximum_leverage、taker_fee_rate、slippage_rate、output_dir、可选 data_source。相对路径按配置目录解析。不得混入独立成员输入、成员参数或额外成本场景。

固定四成员、固定顺序，成员均单独管理同样的初始账户，**不是组合**：

1. `ema_20_50`：V1 EMA20/50。
2. `bollinger_20_2`：V1 SMA20 / 2倍总体标准差布林带。
3. `usdt_cash`：USDT 现金，不持仓、不计利息，费用/Funding/收益/回撤均为零，Sharpe 不可算。
4. `btcusdt_perpetual_long_hold`：**BTCUSDT U 本位永续多头持有基准，不是现货买入持有**。start 的 1m Open 按统一 position_fraction 开多，不再平衡，持有到 end，使用 V1 滑点、双边手续费、实际时点 Funding、Mark 估值和末分钟 close 结束平仓。

基准通过同一引擎目标方向执行，不另写账户逻辑。可复核成员配置使用策略名 `cash` / `btc_perpetual_long_hold`，参数为空，可用 backtest 重放。EMA/布林规则保持原样。

共享的数据只读加载一次，以 EMA 至少150根预热要求统一校验；四类数据、市场、区间、初始权益和仓位规则相同。Funding 仍限 `[2020-01-01,2026-08-01)` 的已核验 UTC 00/08/16，整数延迟 `[0,+47]ms`，一对一匹配且保留实际时间；任何异常失败。最终发布前检查源文件哈希未变化。

## 2. 固定成本场景

每个场景对每个成员完整重新运行（4×3=12），不从原结果减估算成本：

| 场景 | fee | slippage |
|---|---|---|
| `base` | 配置原值 | 配置原值 |
| `slippage_x2` | 原值 | 原值×2 |
| `fee_and_slippage_x2` | 原值×2 | 原值×2 |

历史 Funding 的时间、费率、Mark 不变，金额随重新计算的真实持仓数量变化。每个场景内成本假设共享；它们是研究假设，不是交易所实际费率。倍增后不满足 V1 `[0,1)` 约束时整体失败，不截断费率。

## 3. 全区间及分期口径

全区间复用 V1 summary：净盈亏/净收益、期末权益、日历年化、分钟收盘最大回撤、完整日 Sharpe、交易数、fees/slippage/Funding/gross 等。保持四份成员原始报告及完整配置。固定顺序展示，不按盈利淘汰或排名。

月/年报告从**同一连续账户权益曲线**截取，不重新初始化账户，不月末/年末平仓，也不把交易整体盈亏/Funding 归入退出期：

- 日历期按 UTC 月/年 `[calendar_start,calendar_end)`，实际片段 `[max(start,calendar_start),min(end,calendar_end))`；不输出零长度期间。
- 左边界取该时点已完成分钟的账户状态（运行起点为 initial），同点 Funding/订单属于之后的片段；右边界取同样的状态。运行 end 则取终点平仓后最后一行，包括 V1 结束费用。
- 收益 = 右边界权益 / 左边界权益 − 1，净权益变动 = 两者之差。边界同值被相邻期共享；复合月/年收益可与全区间核对。
- 分期回撤：初始化该片段峰值为左边界权益，再纳入片段内全部分钟收盘样本及实际 end 的终点结算。仅局部峰值，不继承此前月份的峰值。可能遗漏分钟内价格/Funding 波动，与 V1 相同采样限制。
- 输出 calendar/实际边界、complete/partial 标记、有效天数与分钟数、边界权益、收益及分期回撤。首尾不完整月/年仅计算实际片段，不外推为完整期，不年化分期。
- 不输出分期交易数/交易胜率、费用、Funding 或整笔盈亏归属，避免不准确的跨期归集。

## 4. 原子输出与失败

独立 `output_dir/compare-*` 目录：

- `comparison.json`：版本、共享配置、数据路径/SHA/覆盖、来源、Git commit/dirty/源文件哈希、成本场景、每个成员完整配置/指标、分期口径、成员原始报告相对路径和文件哈希、限制。
- `comparison.csv`：12行全区间成员/场景指标与原始报告相对路径。
- `periods.csv`：12组的月度/年度片段。
- `report.md`：简明全区间、分期及成本假设说明与原始报告链接，统一标题“探索性历史比较 / 分期验证”。
- `reports/<scenario>/<member>/`：summary.json、trades.csv、equity.csv、manifest.json；固定相对路径，原配置 output_dir 使用稳定公共目录，不把随机 staging 路径写进内容。

任一成员输入/计算失败或触发 non_positive_equity，整体非零退出并报告场景/成员/时间/原因；不发布成功目录、部分成功比较或删掉失败成员的排名。私有 staging 全部清理。相同输入、配置、代码与依赖环境生成全部文件相同字节；独立外层随机目录名不进报告内容。

## 5. 真实数据完整性选择（先固定规则，再看结果）

较长区间选择规则：按已核验 Funding 范围及 canonical 覆盖中的**完整 UTC 月**顺序检查，月开始前须有150根完整4H预热。每月要求合约1m、Mark1m严格唯一递增、无缺口、有限有效OHLC；4H连续且预热充分；Funding（含转换所保留的边界证据）计划、数值、Mark齐全。任何缺失文件、校验失败、缺口、无效数值/预热/Funding Mark均标为不可用并记录文件、时间和原因，不插值、不补价。

扫描仅输出数据质量，不计算策略结果。已有探索区间仍是已见数据，所有结果均是探索性历史比较 / 分期验证，不是独立 OOS 或盈利证明。

## 7. 第二阶段：固定策略多窗口验证（基线 e280dba）

先确定本节规则，保存数据质量选择记录及SHA，再运行任何窗口的策略。第一阶段compare及最早连续12个月选择保持兼容。沿用第5节完整UTC月、150根连续4H预热、严格合约/Mark分钟网格、实际毫秒Funding/边界证据、canonical身份及官方ZIP/CHECKSUM，不补值、不绕过校验。

### 7.1 固定选择

从已核验Funding范围和canonical覆盖交集中的最早完整月顺序扫描；每6个连续合格完整月组成一个窗口，选定后从结束月份继续寻找；不合格/缺失月打断候选，不跨缺口拼接。最多最早4个互不重叠窗口，按时间展示，不按收益替换。少于4个保存实际数量、不可用月份及扫描结束原因；不缩短凑数，少于2个明确不能完成多窗口真实验证。

在原只读质量工具增加 `--mode study`；默认模式仍为第一阶段的12月规则。study选择JSON记录模式/固定policy、源身份/哈希、逐月质量/缺口、窗口label/start/end/months、数量及停止/不足原因、`strategy_results_used=false`、已见数据边界。JSON必须先写到不存在的新路径并计算SHA，再转换新的标准输入。标签按选择顺序 `window-01`～`window-04`。所有窗口仍是已见历史数据，不是独立OOS；记录与此前2020-02及366天区间的实际交集。

### 7.2 配置与入口

`qfs study --config configs/study.json`。JSON顶层：symbol、initial_equity、position_fraction、maximum_leverage、taker_fee_rate、slippage_rate、output_dir、selection_evidence（path/sha256）、windows。windows每项仅label/start/end/data四路径/data_source，公共资金/仓位/成本不得分成员或窗口覆盖。路径相对配置目录，保留完整来源及选择证据。

要求1～4个窗口，UTC月首00:00边界，精确6个日历月，严格时序、非重叠、标签唯一且安全。选择证据SHA匹配、固定study policy及逐月质量顺序有效，重新从质量标记计算窗口身份，必须与证据及配置全列表一致；不得手动挑选子集。公共假设通过同一V1配置/费用倍增校验，各窗口来源身份与选择记录相同。没有数据质量记录/哈希或无法关联时失败，不能伪称预先选择。

窗口之间是独立实验，均从相同初始权益开始；窗口内部复用完整4成员×3场景及连续分期。没有跨窗口连续净值、复合收益或合并年化，没有新策略/搜索/组合。

### 7.3 输出与失败

独立 `output_dir/study-*`：`study.json`、`study.csv`、`report.md`，以及 `windows/<label>/` 的完整52文件comparison原报告。JSON记录完整规范化study配置、选择证据内容/路径/SHA、代码/依赖版本、各窗口覆盖/数据/报告哈希和稳定相对链接、所有逐窗口指标。CSV按窗口时间、原场景及成员固定顺序，包含净收益、年化/Sharpe、回撤、交易数、fees/slippage/Funding及同场景相对现金和永续的收益差。

收益差单位明确为**百分点**：100×(成员total_return−同窗口同场景基准total_return)，不是相对比例。保留全部结果，不排名、淘汰、选最优窗口或显著性推断；不把窗口当作独立统计样本。Markdown简明逐窗口表及原报告链接。

### 8.1 独立准备

`qfs prepare --manifest <JSON> --start <UTC> --end <UTC> --output <新目录>`。manifest仅声明symbol=BTCUSDT与archives有序列表；每项kind=trade_1m/mark_1m/funding、path、本地CHECKSUM路径、官方HTTPS URL及ZIP SHA-256（路径相对manifest）。只支持已审计历史范围和官方monthly存档。不得依赖旧canonical或其manifest；旧原始存档可只读复用，canonical只作可选验收对照。官方路径/市场/周期/月/文件名、ZIP与CHECKSUM以及声明SHA相符；CSV字段/单位以已检查原始格式为准，文件及拼接不能排序/去重掩盖损坏。

从合约1m完整连续240根聚合UTC4H：first open/max high/min low/last close/Decimal volume总和，保留start.floor(4h)前150根预热；分钟尾部不足4H不发布未完成聚合。Funding使用原始calc_time整数毫秒、8小时字段及固定计划，关联实际时间所在分钟的官方Mark Open；包含起止旁47ms边界证据，证据Mark也必须真实存在。Mark执行表仅[start,end)，不替换/插值；所有原始输入先验证字段、时序、数值，再切片，四类标准文件由原严格loader复验。

全部四Parquet及provenance在私有staging完整成功才发布到不存在的新目录，失败清理、禁止写进源目录/覆盖原数据。记录官方对象及ZIP/CHECKSUM/manifest/标准文件SHA、覆盖、聚合与Mark关联口径及已见数据属性；固定输入/配置/代码下字节可重复。准备与回测分离。本轮优先本机已核验存档，无下载器需求；若必要才有限超时/重试下载官方任务必需存档。
