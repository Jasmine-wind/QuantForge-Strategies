# QuantForge-Strategies V1 需求与实现规格

本文件是 V1 的唯一业务规格。实现、测试、CLI 与报告口径都以此为准；未列入 V1 的功能不得自行扩展。

## 1. 项目目标与范围

QuantForge-Strategies 是面向经典量化策略研究的本地离线回测工具，长期目标是经过验证后逐步发展到模拟交易与受控自动交易。V1 只交付可信、可重复的历史回测闭环，不连接交易账户、不提交真实订单。

V1 范围：

- 市场：Binance BTCUSDT U 本位永续合约，单交易标的。
- 策略决策周期：4H；执行近似：1m 合约 K 线。
- 策略：EMA 双均线交叉、布林带均值回归。
- 交易：单仓、不叠加，Long / Short / Flat。
- 成本：taker 手续费、不利滑点、历史 Funding。
- 初始权益默认 10,000 USDT，可配置。
- 本地 CLI，从本地 Parquet 数据离线运行；Python 3.11+、Pandas/NumPy、pytest，只引入完成闭环所需的依赖。

V1 不做：机器学习预测、自动调参、策略搜索、多资产、策略组合、Web、实时行情、模拟盘、实盘、完整保证金与强平模型、统计显著性检验。上述长期方向不能改变 V1 的交付范围。

## 2. 数据输入与校验

回测不在运行时访问交易所。配置文件明确给出数据路径、策略、时间区间、资金和成本参数。大体量行情文件不提交到 Git。

规范化输入采用 UTC 时间戳：

- 4H K 线 Parquet：open_time、open、high、low、close、volume。
- 1m 合约 K 线 Parquet：open_time、open、high、low、close、volume。
- 1m Mark Price Parquet：open_time、mark_open、mark_high、mark_low、mark_close。
- Funding Parquet：funding_time、funding_rate、funding_mark_price。

时间区间左闭右开 [start, end)。4H K 线以 open_time 标记；open_time 加 4 小时为该 K 线的完成时点。策略只可读取完成的 4H K 线。start 之前的数据只用于指标预热，不得在预热区间开仓。

运行前必须校验：时间戳可解析且统一为 UTC；时间严格递增、无重复；价格和费率为有限数值；OHLC 关系有效；回测区间内所需 1m 合约价与 Mark Price 连续且无缺口；4H 数据覆盖信号区间；Funding 事件无重复且价格、费率齐全。缺失、损坏或无法对齐时，回测失败并指出文件与时间；不得静默跳过、插值或以合约价替代 Mark Price。

### 旧 QuantForge 的数据复用

数据源参考仓库：https://github.com/Jasmine-wind/QuantForge

实现前先查看旧仓库的数据目录、数据说明、字段、时间戳口径、版本与来源记录，确认是否具备本规格要求的 4H、1m、Mark Price 和 Funding 数据。只复用经过核验的原始数据或小型格式转换逻辑；不得复制整个旧研究架构、不得把旧合成数据模拟器直接当作历史回测执行引擎，也不得修改旧仓库。

若旧数据与规范不匹配，新增边界清晰的本地 Parquet 读取/转换层，并保留原始来源、覆盖区间和文件校验信息。首个里程碑可用固定的小型合成数据做正确性测试，但合成数据不能用于宣称策略历史表现。

旧 QuantForge 已研究过的时间段不因迁移仓库而成为独立样本外数据。V1 结果只能称为探索性历史回测。

## 3. 策略规则

所有策略只读取已完成的 4H 收盘数据并生成方向信号。策略不负责成交价、仓位、手续费、账户余额或绩效统计。参数可配置；V1 不提供参数优化。

### EMA 双均线交叉

默认快线 EMA 20、慢线 EMA 50，使用 4H close，按递推 EMA（span 参数，adjust=False）计算。至少使用 start 前 150 根 4H K 线预热；信号只在 start 及之后产生。

- 金叉：上一根有效 K 线快线小于或等于慢线，当前快线大于慢线，产生 Long。
- 死叉：上一根有效 K 线快线大于或等于慢线，当前快线小于慢线，产生 Short。
- 初始状态为 Flat；只有回测区间内出现交叉才入场。方向保持到下一次相反交叉。
- 反向信号按第 4 节顺序执行，不能在同一成交事件内同时平仓和反手。

### 布林带均值回归

默认 SMA 20、标准差倍数 2。窗口只包含当前及之前已完成的 4H close；总体标准差使用 ddof=0。

- Flat 时，收盘价由带内穿越下轨之外，产生 Long；由带内穿越上轨之外，产生 Short。必须是穿越事件，不因价格连续处于轨外而重复入场。
- Long 时，收盘价由中轨下方穿越至中轨或上方时平仓；Short 时，收盘价由中轨上方穿越至中轨或下方时平仓。
- 持仓期间忽略相反方向的入场触发；平仓后等待新的轨道穿越信号，不在同一根 4H K 线上反手。
- 指标窗口无效时不产生信号。

## 4. 成交与事件顺序

信号时间 T 等于产生信号的已完成 4H K 线 close_time。使用 open_time 等于 T 的 1m 合约 K 线 Open 作为第一可执行参考价；若该 1m 数据缺失，则本次回测无效，不能向后寻找价格。

每个 UTC 时间点依次处理：

1. Funding 结算，只对结算前已经持有的仓位计费。
2. 若此时有 4H K 线完成，使用刚完成的 K 线计算信号。
3. 执行在该时间点到期的订单，基准价为 open_time 等于当前时间的 1m 合约 K 线 Open。这样可在不读取未完成 K 线的前提下，用 4H close_time 对齐的下一分钟开盘成交。
4. 分钟结束时用对应 Mark Price close 更新浮动盈亏和权益。

订单均按市价 taker 处理。以滑点率 s 和 1m Open 参考价 p 计算成交价：买入为 p × (1+s)，卖出为 p × (1-s)。每次成交手续费为 abs(quantity × 成交价) × taker_fee_rate；开仓和平仓分别收费。报告记录参考价、成交价、手续费和滑点成本。

仓位方向由策略决定，开仓目标名义金额为成交前权益的 50%，且不得超过当时权益的 1 倍。quantity = 目标名义金额 / 模拟成交价。每次入场按当时权益重新计算；持仓中不加仓、不减仓、不再平衡。V1 不模拟交易所数量步进、最小名义金额和完整保证金规则，报告须列明该限制。

滑点成本按 abs(quantity) × abs(模拟成交价 - 参考价) 单独记录；它已通过不利成交价反映在盈亏中，不得再从权益重复扣除。

反向信号出现时，先在该信号对应的可执行 1m Open 平掉当前仓位，再在下一根 1m Open 开反向仓；两次成交分别计入费用和滑点。只有策略目标仍为该反向方向时才开仓。

区间结束仍有持仓时，在最后一根有效 1m K 线 close 按市价平仓，应用滑点与 taker 费，退出原因标记为 end_of_test。这是回测窗口处理规则，不是策略信号。

## 5. 账户与 Funding

账户按 USDT 线性合约核算。Long 的 signed_quantity 为正，Short 为负。

- 已实现盈亏 = signed_quantity × (平仓成交价 - 入场成交价)。
- 未实现盈亏 = signed_quantity × (当前 Mark Price - 入场成交价)。
- 权益 = 钱包余额 + 未实现盈亏。钱包余额 = 初始资金 + 已实现盈亏 - 手续费 + Funding 现金流。滑点通过模拟成交价影响已实现和未实现盈亏，单独报告但不重复扣款。
- Funding 现金流 = -signed_quantity × funding_mark_price × funding_rate。正费率时 Long 付费、Short 收费；负费率反之。仅对结算时已持有的仓位计费。
- 权益小于或等于 0 时停止新增交易，报告失效时间与原因。V1 不模拟维持保证金、强平价格或强平手续费；报告必须说明其不具备实盘保证金风险精度。

## 6. 绩效与报告

至少输出以下指标，计算口径固定：

- 总收益率 = 期末权益 / 初始权益 - 1。
- 年化收益率按实际日历天数计算：(期末权益 / 初始权益)^(365 / 回测天数) - 1；权益非正或区间无效时不可计算。
- Sharpe 使用完整 UTC 日末权益计算日收益，无风险利率为 0，年化系数为 sqrt(365)；回测开始或结束处不完整的 UTC 日不纳入 Sharpe。少于两个有效日收益或标准差为 0 时不可计算。
- 最大回撤基于包含初始权益的完整 1m Mark Price 权益序列。
- 胜率按已完成交易的净盈亏大于 0 计算；净盈亏包含该笔交易手续费、滑点和持仓期间 Funding。
- 平均盈亏比 = 盈利交易平均净盈亏 / 亏损交易平均净盈亏绝对值；Profit Factor = 盈利交易净盈亏总和 / 亏损交易净盈亏绝对值总和。分母为 0 或无适用交易时不可计算。
- 输出交易数、平均持仓小时数、毛/净盈亏、手续费、滑点成本、Funding 净额。

每次运行生成独立目录，至少包含：

- summary.json：指标、口径版本和限制说明。
- trades.csv：每笔交易、方向、数量、入场/退出时间、参考价、成交价、毛/净盈亏、手续费、滑点、Funding、退出原因。
- equity.csv：UTC 时间、钱包余额、未实现盈亏、权益、Mark Price。
- manifest.json：完整配置、数据文件路径与 SHA-256、覆盖区间、市场与数据来源说明、代码 Git commit SHA、运行口径版本。

固定输入、配置和代码版本必须确定性地产生相同输出。运行失败须返回非零状态并指出原因；不得生成看似成功的部分报告。

## 7. CLI 与配置

提供本地命令：**qfs backtest --config <配置文件路径>**

配置为 JSON，至少包含：strategy 名称与参数、symbol、start/end、四类输入文件路径、initial_equity、position_fraction、maximum_leverage、taker_fee_rate、slippage_rate、output_dir。

示例基准配置：初始资金 10,000 USDT；仓位比例 0.50；上限 1.0 倍；taker_fee_rate 0.0005；slippage_rate 0.0005。费率和滑点是显式可改的回测假设，必须原样记入 summary 和 manifest。Binance 费率可能按账户等级和优惠变化，使用者应按实际费率调整；参考：https://www.binance.com/en/fee/futureFee

V1 不需要数据库服务、Web 服务或联网数据下载器。

## 8. 实施顺序

1. 检查新仓库和旧 QuantForge 数据格式，建立最小依赖配置及规范化本地数据读取/校验。
2. 实现 EMA 信号及无前视偏差测试。
3. 实现单仓账户、1m 执行、滑点、手续费、Funding、Mark Price 权益曲线和终点平仓；用确定性小数据逐事件核算。
4. 提供 EMA CLI 端到端回测及 JSON/CSV 报告。如有已核验真实数据，运行一次真实回测并记录来源；没有则明确说明，不伪造结果。
5. 在同一引擎上实现布林带并添加边界测试。
6. 完成测试和使用说明，列出 V1 已知限制。

代码结构围绕数据读取、策略、成交/账户、指标/报告、CLI 划分；不提前引入插件框架、复杂事件总线或不必要抽象。

## 9. 验收标准

- [ ] 能读取并验证 BTCUSDT 4H、1m、Mark Price、Funding 本地数据；数据重复、缺失、错序或数值无效时失败并说明时间。
- [ ] EMA 与布林带只使用已完成的 4H K 线，并符合本文件信号规则。
- [ ] 可从 CLI 运行 EMA 回测并生成 summary.json、trades.csv、equity.csv、manifest.json。
- [ ] 1m Open 成交时点、方向滑点、双边 taker 手续费、反向单延迟、Funding 符号、Mark Price 浮盈和终点平仓均有确定性测试。
- [ ] 持仓期间权益与最大回撤随 Mark Price 更新，不只在平仓时计算。
- [ ] 相同输入、配置和代码版本可复现。
- [ ] 报告注明数据来源、运行参数、指标口径、已探索数据的样本外边界，以及强平和交易所过滤器限制。
- [ ] 单元与集成测试通过；合成测试数据只验证逻辑，不作为收益证据。
